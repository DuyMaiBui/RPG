# AuraEngine architecture

AuraEngine is a shared simulation platform: the same simulation implementation
runs in Unity local play and in a headless C# server.

Physics simulation runs entirely in the **C++ kernel** (`AuraEngine.Native`,
Jolt for 3D / Box2D for 2D) behind the backend-independent `IPhysicsWorld`
contract, on every platform including the Editor. C# owns gameplay
(state, systems, commands, domain events) and drives the kernel; there is no
separate C# solver. It is not a Unity Physics replacement and gameplay code
never references Unity physics types. Kernel changes are validated with
`Native/AuraEngine/run_kernel_tests.sh` (the in-Editor native suite crashes
mono's JIT at the P/Invoke boundary).

## Layers

```text
Game.Domain (C# gameplay: state, systems, commands, domain events)
      |
AuraEngine.Simulation  (engine-independent simulation kernel; managed API)
      |
AuraEngine.Physics     (backend-independent abstraction; C++ kernel binding)
      |
AuraEngine.Core        (identity, math, definitions, queries, events, state)
      |
AuraEngine.Native (C++)  -- Jolt 3D / Box2D 2D kernel behind the C ABI
```

Host layers add capabilities without changing simulation authority:

```text
AuraEngine.Serialization   state snapshot/serialize/hash/replay
AuraEngine.Server          headless fixed-tick host
AuraEngine.Unity           authoring, views, transform sync, event dispatch
AuraEngine.Native (C++)    Jolt/Box2D adapters + frozen C ABI
```

## Dependency rules

- `AuraEngine.Core`, `AuraEngine.Physics`, `AuraEngine.Simulation`,
  `AuraEngine.Serialization` and `AuraEngine.Server` are
  `noEngineReferences` assemblies. They never reference UnityEngine, Jolt or
  Box2D.
- `AuraEngine.Unity` is the only UnityEngine-facing layer.
- Native backend choice is an implementation detail below `AuraEngine.Physics`.
  Domain code only sees `IPhysicsQuery`, ids and definition structs.
- Networking/prediction/reconciliation/rollback are future layers and must not
  become dependencies of the core.

## Simulation ownership

`AuraSimulationWorld` owns the entity registry and the physics world. It is the
single source of truth. Unity transforms, MonoBehaviours and presentation are
never authoritative.

- Identity is index + generation. Stale ids are rejected.
- The tick is generated by the host (`AuraServerSimulationHost`,
  `AuraSimulationInstance`), never read from `Time.deltaTime` inside the kernel.
- `Step` order: dispatch commands, run systems, step physics, capture and remap
  events. State hash is computed from detached body states for determinism.

## Physics abstraction

`IPhysicsBackend` creates an `IPhysicsWorld`. A world creates/destroys bodies,
sets kinematic targets, steps, exposes `IPhysicsQuery` and `IPhysicsEventSource`,
and copies detached `AuraBodyState`/`AuraPhysicsEvent` values. Bodies and shapes
are referenced by stable ids, never native pointers.

`NullPhysicsBackend` is an in-process fallback used when no native plugin is
present. It supports body lifecycle and state storage only (no collision
solving, no queries). Jolt and Box2D adapters implement the same contract in
`AuraEngine.Native`.

## Integration with RPG.Simulation

`Assets/Scripts/Simulation` (`RPG.Simulation.Contracts`/`Runtime`) remains the
existing local-authoritative command/update framework and is not modified.
AuraEngine is a separate, parallel kernel with its own ids and envelopes.
A future step can bridge `RPG.Simulation` command handlers onto
`AuraSimulationWorld` systems; until then the two coexist without a cyclic
assembly dependency.
